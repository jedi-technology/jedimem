An in-repo Claude Code plugin is a standing RCE primitive: once the directory is
trusted, an edited hook re-executes with no prompt, no hash check and no diff.

**Why:** a committed `.claude/settings.json` with `extraKnownMarketplaces` plus
`enabledPlugins` gives a genuine zero-command install — and the same path means a
hostile PR that edits `hooks/hooks.json` runs on the next teammate's session.
Codex is strictly better here: it pins each in-repo hook by SHA-256 in the
*user's* global config, so any edit revokes trust until re-approved.

**How to apply:** keep data in-repo and executable code out-of-repo and
version-pinned. If an in-repo hook is required, make it a fixed, tiny, reviewed
shim that only signals an out-of-repo daemon — so editing it buys a socket call,
not arbitrary execution. Never claim `CODEOWNERS` or CI mitigates this; both
reduce to "a human skimmed the diff".
