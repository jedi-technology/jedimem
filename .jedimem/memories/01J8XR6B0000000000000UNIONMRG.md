We tried `merge=union` for append-heavy memory files and rejected it.

**Why:** it does eliminate append/append conflicts on both merge and rebase, so it
looks correct. But union merge takes the union of *lines*, which means it cannot
represent deletion or modification. Measured: one branch corrected a wrong fact
while another appended an unrelated one; after a clean merge, **the corrected fact
and the original wrong fact were both present**. Every correction is silently
undone by the next merge from anyone who hadn't pulled it.

**How to apply:** use one file per memory instead. `merge=union` remains
acceptable only for a strictly append-only log whose entries are never edited or
removed.
