Update checks use `git ls-remote` behind a jittered 24h TTL, run detached, and
never auto-install.

**Why:** the GitHub REST API is unusable for this — unauthenticated limit is
60/hr **per IP**, and measured `304 Not Modified` responses **still decrement
the quota**, so a team behind one NAT exhausts it. `git ls-remote` has a
separate budget and needs no token. The check is detached because anything in
the agent's critical path gets the tool uninstalled, and TTL-jittered so a team
starting work at 09:00 does not stampede the remote.

**How to apply:** claim the TTL window *before* spawning the child, or every
session started before the child writes will spawn another checker. Never
auto-install: new code should run on a machine when its owner chooses the
moment, not when a background process does (threat T1).
